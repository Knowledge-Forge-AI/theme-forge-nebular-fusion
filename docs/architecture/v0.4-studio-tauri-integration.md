# TFSB Studio Tauri 2 and React Integration Boundary

- Status: Current in-repository architecture under ADR 0018
- Application source: `apps/studio`
- Protocol authority: [ADR 0010](../decisions/0010-studio-local-service-protocol.md)
- Release base: public `0.3.0` remains immutable

Studio is an independently locked application in this repository. Shared source
coordination does not merge the root npm package, Studio npm/Cargo locks,
versions, artifacts, capabilities, release records, or rollback identities.

The controlling sequence is TFSB47H bootstrap hardening, TFSB47I sidecar host
and transport, TFSB47J live reads, TFSB47K typed plans, TFSB47L human-agent
evidence freeze, TFSB48 Terminal Nova dogfood, TFSB49 PR/CI and macOS-arm64
qualification, TFSB50 coordinated release candidate, and TFSB51 attended
publication and post-release smoke.

## Authority flow

```text
React/TypeScript UI
  -> closed typed Tauri bridge
  -> Tauri 2 Rust host
  -> supervised TFSB sidecar over local stdio (from TFSB47I)
  -> TFSB domain planners and transactions
  -> workspace/project/source roots
```

TFSB remains the sole parser, canonical read/write, semantic diff, and
transaction authority for `.tfsb` state. Rust owns the fixed host lifecycle,
future sidecar supervision, native selection, framing, and desktop capability
configuration. React receives typed public DTOs and opaque handles, not generic
filesystem, shell, path, process, URL, module, plugin, provider, or model
authority.

TFSB47H implemented only one local window, an explicit two-command application
manifest and capability, a typed zero-argument bootstrap bridge, and a validated
synthetic candidate-review fixture. It has no sidecar, project access, mutation,
background task, plugin, Swift/FFI, updater, signing, or network content.
Command rejection or malformed DTOs fail closed; production does not silently
substitute fixture host success. Plain-browser fixture mode is explicit and
development-only.

## Native selection for future mutation authority

From TFSB47I onward, a path selected through a native dialog may be supplied by
Rust only to the existing `workspace.open`, `project.open`, or `source.open`
methods. TFSB independently validates it and returns an opaque session handle.
React uses handles and typed IDs thereafter.

For an import target, TFSB—not Rust or React—proves real ancestry, non-symlink
confinement, and the absence of `.tfsb`. Auxiliary maps and manifests use the
exact closed `source.open` purpose. TFSB revalidates handles during planning and
the underlying file during apply; the host must not silently reopen, replace,
or emulate authority with a temporary file.

Protocol stdout remains machine-only newline-delimited JSON. Sanitized logs use
stderr. The host must not expose a generic shell, filesystem bridge, arbitrary
command name, or “run TFSB CLI” surface. Mutations use typed plan methods and
`plan.apply`, preserving authentic session-bound, single-use authority and
stale-state rejection.

TFSB47I replaces that bootstrap with the five-command typed surface in ADR
0019. The Rust host verifies the complete fixed Node-runtime payload before
spawn, negotiates protocol 1.2, retains session authority, and owns bounded
shutdown/reaping. Native dialog selection is Rust-only and selected paths pass
directly to `project.open` or `source.open`; the webview receives only opaque
handles and public DTOs. The capability grants no dialog, shell, filesystem,
or generic event permission.

The TFSB47J layer adds one closed typed read command and a method-specific
frontend client. Application state owns host state, selected public project and
source DTOs plus opaque handles, the active view, per-view read state/cursor,
and ephemeral visual URLs. Identity replacement or host termination clears
dependent state and revokes images. React has no path, nonce, request ID,
generic invoke, shell, filesystem, or `.tfsb` parsing authority.

Signing, notarization, installer behavior, other platforms, and typed plan UX
remain later owned phases. Starlight Theme Lab is a post-release documentation
track and adds no architecture or dependency here.
